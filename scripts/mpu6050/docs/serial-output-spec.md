# MPU-6050 姿态遥测台 — 下位机串口输出规范

版本：1.1  
日期：2026-11-13  
变更：默认波特率调整为 115200。  
适用对象：ESP32 / MPU-6050 下位机固件开发 Agent

## 1. 目标

网页仪表盘通过 Web Serial 逐行读取下位机串口数据。请下位机按本规范输出，**一行一个 JSON 对象**。网页不需要握手命令或应答，只要持续输出即可。

推荐下位机只实现本规范中的 **JSON 格式**。网页虽然兼容 CSV 和键值对，但 JSON 是本次对接的正式格式。

## 2. 物理层与传输

| 项目 | 要求 |
|---|---|
| 端口 | ESP32 的 USB/UART 串口 |
| 波特率 | **115200**（与网页默认值一致，8N1） |
| 数据位 / 校验 / 停止位 | 8 / None / 1 |
| 流控 | 无 |
| 编码 | UTF-8 或 ASCII |
| 分隔 | 每条消息以 `\n` 结尾；兼容 `\r\n` |
| 频率 | **推荐 50 Hz（20 ms 一帧）**；115200 下建议不超过 60 Hz |
| 格式 | 每行一个完整 JSON 对象，不能跨行，不能是 JSON 数组 |
| 网页时间戳 | 由上位机按收到时刻生成，下位机**不需要**发送时间戳 |

115200 bps、8N1 的理论有效带宽约为 11.5 KB/s。50 Hz、每行约 130 字节的数据量约为 6.5 KB/s，余量充足。若后续需要更高采样率，可把固件和网页同时改为 921600 等更高波特率。

串口启动日志（如 `READY`）网页会忽略；正式输出开始后请不要再混入日志，以免占用原始数据窗口。

## 3. 标准 JSON 帧

### 3.1 字段定义

所有数值必须是有限数字（不能是 `NaN`、`Infinity`、字符串或 `null`）。键名必须使用下面的大小写。

| 键 | 类型 | 单位 | 必需 | 含义 / 推荐范围 |
|---|---|---|---|---|
| `roll` | number | ° | 是 | 横滚；推荐 `-180 ~ +180` |
| `pitch` | number | ° | 是 | 俯仰；推荐 `-90 ~ +90` |
| `yaw` | number | ° | 是 | 偏航；推荐 `-180 ~ +180`，也可以累计 |
| `ax` | number | g | 是 | 机体 X 轴加速度 |
| `ay` | number | g | 是 | 机体 Y 轴加速度 |
| `az` | number | g | 是 | 机体 Z 轴加速度；静止水平时约为 `+1.0` |
| `gx` | number | °/s | 是 | 机体 X 轴角速度 |
| `gy` | number | °/s | 是 | 机体 Y 轴角速度 |
| `gz` | number | °/s | 是 | 机体 Z 轴角速度 |
| `temp` | number | °C | 否 | 传感器温度；没有可省略 |

建议精度：

- `roll` / `pitch` / `yaw`：2 位小数
- `ax` / `ay` / `az`：3 位小数
- `gx` / `gy` / `gz`：1 或 2 位小数
- `temp`：1 位小数

一行的建议最大长度 < 512 字节。未知字段可以被网页忽略，但建议只发送上述字段。

### 3.2 标准单行示例

下面为了阅读做了换行，实际串口必须发送**完整的一行**：

```json
{"roll":1.25,"pitch":-3.40,"yaw":128.60,"ax":0.018,"ay":-0.012,"az":0.997,"gx":0.4,"gy":-0.2,"gz":1.1,"temp":31.5}
```

对应的纯文本原始行：

```text
{"roll":1.25,"pitch":-3.40,"yaw":128.60,"ax":0.018,"ay":-0.012,"az":0.997,"gx":0.4,"gy":-0.2,"gz":1.1,"temp":31.5}\n
```

无需序号、时间戳或数组包装，也不要输出 `undefined`、`nan` 或 `inf`。

## 4. 坐标轴与正负号约定

网页三维视图默认按以下约定解释角度。**请下位机统一按这个约定输出**，即使 MPU-6050 的实际安装方向不同，也应在固件内部先完成轴交换/取反。

### 4.1 机体坐标

- X+：朝向设备前方（“机头”）
- Y+：朝向设备左方
- Z+：朝上（垂直于 PCB 顶面）
- 三轴构成右手坐标系

### 4.2 角度定义

| 角度 | 正方向 | 静止姿态的加速度特征（约值） |
|---|---|---|
| `roll` | 右侧下沉 | `roll=+30°` → `ay≈+0.50 g`，`az≈0.87 g` |
| `pitch` | 机头抬起 | `pitch=+30°` → `ax≈+0.50 g`，`az≈0.87 g` |
| `yaw` | 俯视逆时针（左转） | 水平静止时角度不变；左转过程中 `gz` 为正 |

水平静止、机头朝 +X 时：

```text
roll ≈ 0°, pitch ≈ 0°, ax ≈ 0, ay ≈ 0, az ≈ +1.000 g, gx ≈ gy ≈ gz ≈ 0
```

### 4.3 角速度正方向

机体为右手系时，角速度方向遵循右手定则：

- `gx` 为正：向“右侧下沉”的方向转动
- `gy` 为正：向“低头”的方向转动
- `gz` 为正：向“左转（俯视逆时针）”的方向转动

因此，如果固件把 `gy` 直接积分成 Pitch，需要先取反；本规范要求：

```text
Roll  += gx * dt
Pitch += (-gy) * dt
Yaw   += gz * dt
```

Roll / Pitch 用加速度做互补滤波时：

```text
roll  = atan2(ay, az)
pitch = atan2(ax, sqrt(ay*ay + az*az))
```

### 4.4 如果安装方向不一致

请优先在固件内部完成轴映射，保证最终输出的 JSON 满足第 4 节的符号约定。网页右上角的「视图校准」只做 Roll / Pitch / Yaw 单项取反，用于最后的视觉微调，不能替代固件中的轴交换。

## 5. 推荐的 ESP32 输出代码

下面的片段只负责把已经计算好的物理量输出为标准 JSON，不包含 MPU-6050 的初始化与滤波。

```cpp
#include <math.h>

constexpr uint32_t SERIAL_BAUD = 115200;

void sendTelemetry(float roll, float pitch, float yaw,
                   float ax, float ay, float az,
                   float gx, float gy, float gz,
                   float tempC) {
  const float values[] = {roll, pitch, yaw, ax, ay, az, gx, gy, gz, tempC};
  for (float value : values) {
    if (!isfinite(value)) return;  // 绝不把 nan / inf 送进 JSON
  }

  char line[192];
  snprintf(line, sizeof(line),
           "{\"roll\":%.2f,\"pitch\":%.2f,\"yaw\":%.2f,"
           "\"ax\":%.3f,\"ay\":%.3f,\"az\":%.3f,"
           "\"gx\":%.1f,\"gy\":%.1f,\"gz\":%.1f,\"temp\":%.1f}\n",
           roll, pitch, yaw,
           ax, ay, az,
           gx, gy, gz, tempC);
  Serial.print(line);   // 注意：格式串已经包含 \n，不要再 println() 加一次
}
```

调用方示例：

```cpp
Serial.begin(SERIAL_BAUD);
// ... MPU-6050 初始化 ...

// 推荐每 20 ms 调用一次，输出滤波后的数据
sendTelemetry(roll, pitch, yaw, ax, ay, az, gx, gy, gz, tempC);
```

若使用 ESP32-S3 / ESP32-C3 等原生 USB CDC，波特率设置可能只影响网页端的显示配置，但网页和固件仍应保持一致。

## 6. 验收测试

把下位机连接到网页后，完成以下测试。下表中的姿态值应能在网页的实时读数和 3D 模型上对应显示。

| 测试姿态 | 应输出（约） | 网页表现 |
|---|---|---|
| 水平静止，机头朝前 | `roll=0, pitch=0, ax=0, ay=0, az=+1.000`，角速度近 0 | 模型水平、不倾斜 |
| 机头抬起约 30° 后静止 | `pitch≈+30`，`ax≈+0.50`，`az≈+0.87` | Pitch 为正，模型机头抬高 |
| 右侧下沉约 30° 后静止 | `roll≈+30`，`ay≈+0.50`，`az≈0.87` | Roll 为正，模型右侧下沉 |
| 从上方看向左转（逆时针） | `yaw` 增大，转动时 `gz>0` | 模型水平旋转，Yaw 对应变化 |

同时确认：

- 数据连续输出，速率约为 50 Hz（网页「数据速率」应接近 `50.0 Hz`）
- 串口监视器关闭，因为网页需要独占串口
- 每行都是可独立解析的 JSON；断线后不会出现半行

可把 [serial-sample.jsonl](serial-sample.jsonl) 作为合法行样例；文件中的每一行都是完整帧。

## 7. 兼容性说明

网页解析器还兼容以下格式，但本次对接**不需要实现**：

- CSV 9 列：`roll,pitch,yaw,ax,ay,az,gx,gy,gz`
- CSV 6 列：`ax,ay,az,gx,gy,gz`
- 键值对：`roll=... pitch=... yaw=... ...`

如果下位机采用其他字段名，可以继续沿用，但需确认网页的自动识别能匹配；最稳妥的做法仍然是使用本规范中的标准 JSON 键名。

## 8. 给固件 Agent 的最短交付清单

1. 波特率 `115200`，8N1，无流控。
2. 50 Hz，每行一个 JSON 对象，以 `\n` 结尾。
3. 必发字段：`roll,pitch,yaw,ax,ay,az,gx,gy,gz`；`temp` 可选。
4. 单位：角度 `deg`，加速度 `g`，角速度 `°/s`，温度 `°C`。
5. 遵循第 4 节坐标和符号约定；安装方向不同时在固件中先做轴变换。
6. 不输出 nan / inf；不要把一行 JSON 拆成多行；`Serial.print` 后不要重复 `println`。
7. 完成第 6 节的四个验收姿态。
